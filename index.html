      How this was made

      1. Collect. Searched the Meta Ad Library (Canada, active ads) for each brand, scrolled to load results, and saved the page. Single ads were added as screenshots.
      2. Extract. A small Python script reads each saved page and pulls out the facts: library ID, start date, post text, headline, CTA, image or video.
      3. Tag with AI, using a fixed taxonomy. Claude viewed every creative (static images, and the first 3 seconds of PolicyMe's videos) and tagged product, format, angle, audience, offer and proof. Tags had to come from a fixed list. Anything not visible was marked unclear rather than guessed.
      4. Human review. I reviewed the tags, approved four new angles where ads didn't fit the list, and excluded ads that weren't insurance or were outside PolicyMe's market.
      5. Build. A build script merges facts and tags into one ads.json. This page reads that file, so adding ads and re-running updates everything.

      What was collected

        Limits

        • Meta shows no spend or results for Canadian commercial ads. Ad longevity is a signal, not proof of performance.
        • The Ad Library loads results as you scroll, so each brand's sample is the ads that had loaded when the page was saved, not every active ad.
        • Tags are judgment calls made with a fixed list. The reasoning for each one is in that ad's notes in the gallery.

        How it could run on autopilot

        The pipeline is already split into steps a scheduler could run weekly: save each brand's Ad Library page, extract, fetch new video media before the links expire, and send only new library IDs for tagging. Comparing each week's IDs against the last would show which ads launched, which stopped, and which keep running. That gives a growth team a live competitor feed instead of a one-off snapshot.
